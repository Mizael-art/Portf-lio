Problemas que Quebram o Backend

Crítico — Bloqueadores de Implementação
🔴Sem fluxo de cadastroRegisterInfo/Photo/Finish ausentes. O backend Supabase cria perfil com name, nickname, city, state, preferredPosition, dominantFoot, photoUrl — sem a tela esses campos não têm como ser coletados
🔴Sem Tab Bar globalA navegação principal (INÍCIO/GRUPOS/PERFIL) não existe em nenhuma tela. Implementador não sabe como construir a estrutura raiz do app
🔴Timer sem controles essenciaisGameTimerScreen precisa de: input de duração, PAUSAR, PARAR, seletor de rotationRule, lista de sessões. Sem esses, a lógica de timerService é inimplementável pelo design
🔴CreateGame sem designCreateGameScreen tem os campos mais complexos do app: tipo de jogo (Rachão/Resenha/etc), teamsCount, rotationRule, data/hora, localId. Sem design, implementador inventará o layout
🔴ParticipantsScreen ausenteConfirmar presença dos jogadores (confirmar/recusar) é operação crítica do fluxo. Sem design
🔴TeamsScreen ausenteSorteio de times é funcionalidade core do app. Sem design para o fluxo de sorteio automático/manual
🔴Rating "88" não existe no bancoFIFA card mostra rating 88 mas não há coluna de rating no schema Supabase. Pode gerar confusão na implementação. Remover ou mapear para stat real (ex: média de gols)
🔴Sem estados de loading/erro em nenhuma telaImplementador precisará inventar como mostrar loading e erro em cada tela individualmente. Design deve especificar skeleton screens ou spinner patterns
🔴Sem tela de Settings/LogoutLogout é funcionalidade de auth essencial. Sem SettingsScreen, usuário fica preso na conta
🟡Dois designs duplicados para mesma telagame_detail_hub_1 e _2 / match_timer e game_timer — geram ambiguidade. Implementador não sabe qual seguir
